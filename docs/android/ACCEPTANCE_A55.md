# Aceptación Android del incremento funcional

## Diagnóstico aislado

El A55 SM-A556E con Android 16 tenía el APK Debug device de #87, SHA b35de93bbe1c7ad495ac68161ca1f02462fae091, árbol limpio, API http://127.0.0.1:18181 y SHA-256 e7e75e343ea9c626657ad3196fe0bc18cee9c9c1e5d1013b12add49e5edcd094. Se comprobó extrayendo el APK instalado y leyendo su marcador. ADB no tenía reversión activa y los puertos aislados no escuchaban. Debug permite HTTP únicamente en loopback y en la dirección del emulador. El WebView Android usa el origen https://localhost.

Se restauraron los servicios aislados en 127.0.0.1 y el túnel 18181 → 18080. Spring respondió 400 a una solicitud inválida, 401 a credenciales inválidas, 200 al login sintético válido y 200 a /api/auth/me con identidad coincidente. /me sin sesión devolvió 401. El origen https://localhost fue autorizado, mientras que http://localhost recibió 403. La causa observada era de disponibilidad/conexión. Estas pruebas HTTP no acreditan una interacción física ni la persistencia de Android Keystore.

El catálogo aislado devolvió siete productos con URL de imagen. Los destinos eran externos a la lista actual. Yamaha y Roland devolvieron 404, Fender falló en la resolución DNS desde esta estación y Pearl redirigió fuera de los destinos comprobados. Se conserva la validación de orígenes y el fallback accesible. Para ver fotos reales en la aceptación, hace falta al menos un producto sintético con fotografía autorizada y verificada en el origen API o Cloudinary. No se cambiaron los datos del catálogo.

## Procedimiento en el Galaxy A55

1. Arrancar solo el clúster marcado TT05 en 55439, Mailpit en 18025 y el Spring aislado en 18080. Usar los launchers y las comprobaciones de identidad de [TT-05](../security/TT05_SESSION.md). Verificar el catálogo por GET y comprobar que el puerto 18080 escucha únicamente en 127.0.0.1.
2. Desde el worktree limpio del HEAD que se quiere aceptar, ejecutar `node scripts/build-android.mjs --environment device --variant debug --api-url http://127.0.0.1:18181`. Revisar sourceSha, sourceTreeDirty, environment, apiBaseUrl y signing en reports/android-packages/device-debug/build-report.json. Comparar SHA-256 del APK mediante Get-FileHash.
3. Con el teléfono conectado, desbloqueado y con depuración autorizada, ejecutar `adb devices -l`. Seleccionar su serial explícitamente en todas las órdenes. Consultar la APK existente con `adb -s <serial> shell pm path com.casademusicacastillo.app`. Extraer base.apk a una ruta de evidencia privada y comparar hash, firma con apksigner y assets/public/cmc-build.json. Si la firma difiere, detener la instalación y conservar los datos.
4. Comprobar `adb -s <serial> reverse --list`. Si falta el túnel o se reinició ADB, configurar `adb -s <serial> reverse tcp:18181 tcp:18080` y volver a listar. El emulador puede usar 10.0.2.2 en la configuración development. El APK device del A55 utiliza el loopback de su túnel.
5. Con autorización explícita del titular y firma Debug compatible, instalar mediante `adb -s <serial> install -r reports/android-packages/device-debug/app-debug.apk`. Confirmar hash de la instalación y mantener el puente activo.
6. Entrar con la cuenta sintética, comprobar catálogo, una foto válida o fallback, descripción formateada y navegación desde cualquier zona principal de la tarjeta. Probar el corazón sin salir del catálogo, abrir el detalle, retirar y comprobar la lista de favoritos. Repetir en ambas orientaciones y con TalkBack.
7. En la cuenta sintética, activar MFA por email si se ha autorizado para la prueba, recuperar el código en Mailpit local y verificar el desafío. Restaurar la configuración de MFA de la cuenta al terminar. Cerrar/reabrir la app para probar restauración y ejecutar logout para comprobar borrado y revocación.
8. Guardar SHA, hash, versión Android, estados HTTP y capturas sin credenciales. Para almacenamiento y Logcat, seguir el verificador de TT-05 solo en emulador cuando se necesite limpiar estado. En el A55, limitar la inspección a la app Debug y registrar únicamente la presencia de ciphertext/ausencia de plaintext, sin imprimir archivos de preferencias, correos, tokens o códigos.
