Un build verde no reemplaza una prueba funcional.

## Clasificación de checks

**Obligatorios del PR:** `Lint, Tests y Build`, `frontend`, `Auditoria de dependencias`, `CodeQL JavaScript y TypeScript`, `Compilar APK Android Debug`, `ACEPTACIÓN móvil DEMO / maestro` y el consolidado `DEVOPS QUALITY GATE`.

**Informativos:** audit completo de dependencias de desarrollo y warnings compatibles de Angular/Gradle/emulador. Se muestran en logs/resúmenes y se atienden cuando son accionables.

**Manuales o condicionales:** API remota, regresión completa, k6 LOAD y k6 STRESS. No deben configurarse como required checks cotidianos porque pueden quedar legítimamente `SKIPPED` o `BLOCKED` por ambiente.

## Activación por rutas y concurrency

- Si el bloque nuevo contiene cualquier archivo fuera de `docs/**` y `*.md`, se ejecutan CI, Security, Integration frontend, Android→Acceptance y k6 inspect.
- Si el bloque nuevo es exclusivamente documental, los jobs pesados anteriores aparecen `SKIPPED / NO APLICA`; el detector y el gate sí aparecen. El gate acepta NO APLICA únicamente bajo esta regla.
- Regression sigue manual. API remota, k6 LOAD/STRESS y dispatch manuales nunca se cancelan automáticamente.
- CI, Security, Integration, Android y Performance cancelan el run anterior del mismo PR al llegar un `synchronize`. Staging cancela un push anterior a `develop` todavía en curso; su dispatch manual se conserva.
